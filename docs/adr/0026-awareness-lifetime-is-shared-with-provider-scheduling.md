# Awareness lifetime is shared with provider scheduling

`YAwareness` exposes synchronous `checkTimeouts()` and serializes native operations, timestamps, and renewal with a recursive lock. Providers start maintenance at construction and keep it running through disconnect and reconnect. WebRTC stops on `destroy()` or deinitialization; Hocuspocus stops on deinitialization. Disconnected checks renew local state without sending and expire remote states. Core awareness creates no timer.

Defaults follow `y-protocols` 1.0.7: check every 3 seconds, renew non-null local state after 15 seconds, and remove remote states after 30 seconds. Test infrastructure is documented in [docs/testing.md](../testing.md).

Initialization enqueues timer startup on the provider actor without opening a connection. Startup is idempotent; reconnect does not replace the timer. Provider tasks sleep without retaining their actor, and cancellation plus a generation ID prevents stopped tasks from checking after terminal teardown. WebRTC destruction is terminal even before connecting or after disconnecting.

Local set, renewal, and clear use origin `"local"`, unless the caller supplies an origin. Every clear advances the local clock and emits change and update, including repeated null; the first clear stores clock 1. `removeStates` ignores absent clients, preserves remote clocks, and advances an active local client's clock. Hocuspocus disconnect clears remote peers at their existing clocks without sending. WebRTC peer close leaves presence until the 30-second expiry; disconnect and destroy remove local presence once with origin `"disconnect"`.

Non-null local setters and idle renewals also emit with origin `"local"`, matching `setLocalState` in `y-protocols` 1.0.7. Local mutation scopes restore the previous origin before delivering queued callbacks, so they cannot inherit an inbound provider or timeout origin.

Swift starts with neither a local state nor local metadata. Yrs creates the first local entry at clock 1, including a first null, whereas JavaScript's `setLocalState` uses clock 0 when metadata is absent. The standard JavaScript constructor first sets `{}` at clock 0, so its first explicit clear also produces clock 1. We retain Yrs's initial clock: applying an absent null at clock 0 can store metadata through the existing Shim ABI, but emits no native events. Matching that internal initialization case would require separate event delivery machinery or a native change. Subsequent local mutations increment normally, and the clock 1 tombstone remains interoperable.

Hocuspocus 4.7.0 does not hold awareness updates until authentication or sync completes. With its default disabled batching, `awarenessUpdateHandler` sends immediately except for the provider's own origin. Provider `send` checks attachment, and the WebSocket transport checks only whether the socket is open, queuing otherwise. `onOpen` awaits an asynchronous token before starting sync, so a renewal can precede the authentication message while token retrieval is pending. Swift keeps this behavior: observing awareness before awaiting the token allows renewals to send on the open socket. Authentication and sync do not gate awareness sends.

Yrs stores clocks and timestamps, but the existing Shim ABI exposes neither timestamp access nor automatic expiry. Swift observes accepted native updates to track time, including unchanged state with an increased clock. Replayed updates do not refresh time. For expiry, Swift applies a batched null update at the existing remote clocks. Native `remove_state` increments remote clocks, which would reject a peer's next renewal. Expiry emits change and update events with `YAwarenessChange.origin` set to `"timeout"`. This requires no Binary Artifact Release.

Native callbacks capture events and origins under the lock. User callbacks are delivered serially after releasing it and after native observer delivery has completed, so they may re-enter on the same thread or access awareness from another thread. Concurrent mutations can finish while another thread delivers callbacks; their events join that delivery queue. Cancellation invalidates queued callbacks without waiting for a callback already in flight. No awareness lock is held across user callbacks or an await. Inbound Hocuspocus updates carry an origin unique to the provider instance so delayed callbacks suppress echoes without suppressing concurrent local updates or forwarding by other providers sharing awareness.

State updates happen immediately, while nested events use breadth-first delivery rather than JavaScript's depth-first delivery; callbacks may arrive late on another thread and should read current state. The single deliverer can deadlock if a callback waits for a thread that is waiting for its own awareness events.

`YSyncProtocol` dispatches decoded messages in Swift without holding the awareness lock across document transactions. Document operations retry only `YError.transactionConflict` from the existing nonblocking `YDoc` APIs. A 5 ms synchronous backoff matches Hocuspocus's transaction retry cadence and avoids spinning. A monotonic one-second deadline per document operation accommodates ordinary writes and short bursts, preserving the native handler's waiting behaviour for normal contention while bounding calls made inside a transaction or commit observer that cannot finish until the call returns. Hocuspocus uses eight attempts because it can reconnect after exhaustion; the core synchronous API has no reconnect recovery, so it allows a longer wait and throws `transactionConflict` at its deadline. Awareness messages use the synchronized apply and encode paths. Custom providers can tag inbound awareness events through `handle(_:awareness:origin:)` to suppress echoes.

The whole batch is decoded before application. A malformed later protocol message rejects the batch without applying its valid prefix, unlike the native handler's incremental decode and apply. Application errors still leave earlier applied messages intact. The handler skips rebuilding unused message payloads, and `JSONDecoder` reads byte arrays directly as `[UInt8]` instead of bridging each byte through `NSNumber`. The existing decode FFI still serializes and parses an intermediate JSON representation; a typed decode FFI is a follow-up requiring a Binary Artifact Release.

If a peer times out our local state at its current clock, Yrs silently increments our clock without emitting an update. Presence is restored at the next renewal, at most 18 seconds later with the default cadence. Local state remains null by default; only non-null local state, including an empty dictionary, supplies idle Hocuspocus keepalive traffic.
